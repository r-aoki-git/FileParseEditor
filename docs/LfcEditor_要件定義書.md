# LfcEditor（LFCファイル編集アプリ）要件定義書

- 作成日：2026-10-21
- 改訂日：2026-10-21

- 対象ファイル形式：`.lfc`
- 開発環境：.NET 8 / C# / WPF / Visual Studio 2022
- 利用するライブラリ：`FileParserLib`（前課題で作成したLFCファイル読み書きライブラリ）

## 1. 目的

`FileParserLib`を利用して、LFCファイルの読み込み・編集・保存を画面から行えるWPFアプリケーション`LfcEditor`を作成する。
本課題では、ライブラリの機能を画面に載せること自体よりも、以下の点を重視する。

- ライブラリの公開APIだけを使って、利用者（アプリ）の立場から必要な機能を実現できるか
- 型が混在する複数値・警告／エラーといったLFCの特徴を、画面上でどう見せ、どう入力させるか
- 不正な入力や保存されていない変更に対して、利用者が意図せずデータを失わないようにすること
- 画面（View）と処理（ロジック）を分離し、画面を操作しなくてもロジックを検証できる構成にすること

---

## 2. 前提

### 2-1. 利用するライブラリ

`FileParserLib`の公開API（`LfcDocument`、`LfcValue`、`LfcDiagnostic`など）だけを使い、内部（`internal`）のクラスには依存しない。
ライブラリの主な仕様は`FileParserLib_要件定義書.md`（v7）と`FileParserLib_基本設計書_10-02.md`のとおりであり、本書ではアプリ側の要件だけを定める。

| ライブラリの機能 | アプリでの用途 |
|---|---|
| `Load` / `CreateEmpty` / `Save` | ファイルを開く／新規作成／保存 |
| `Sections` / `Keys` / `Get` | セクション一覧・キー一覧・値の表示 |
| `Set` / `AddSection` / `Remove` / `RemoveSection` | 値の追加・変更、セクションの追加、キー・セクションの削除 |
| `Diagnostics`、`LfcLoadOptions.ThrowOnError` | 読み込み時の警告・エラーの表示 |

### 2-2. 利用者

LFCファイルの記法を理解している開発者・設定担当者を想定する。LFCの記法を知らない利用者向けの入力補助（ウィザード等）は設けない。

## 3. 機能要件

| No | 機能 |
|----|------|
| 1 | LFCファイルを選択して開ける（ファイルを開くダイアログ） |
| 2 | 新規に空のLFCデータを作成できる |
| 3 | セクションの一覧を表示できる（グローバルセクションを含む） |
| 4 | 選択したセクションのキーと値の一覧を表示できる（値の型が分かるように表示する） |
| 5 | 既存のキーの値を変更できる（複数値・型の混在・値なしを含む） |
| 6 | 選択したセクションにキーを追加できる |
| 7 | キーを削除できる |
| 8 | セクションを追加できる |
| 9 | セクションを削除できる（所属する全キーごと削除。削除前に確認する） |
| 10 | 上書き保存できる |
| 11 | 名前を付けて保存できる（ファイルを保存するダイアログ） |
| 12 | 読み込み時の警告（Warning）・エラー（Error）を、行番号・内容とともに一覧表示できる |
| 13 | 保存していない変更がある状態で、ファイルを開く・新規作成・アプリの終了を行う場合、保存するかを確認する |
| 14 | 保存していない変更があることを画面上で判別できる（タイトルバーに`*`を表示する等） |
| 15 | 入力した名前・値がLFCとして書き出せない場合、データを変更せずにエラーメッセージを表示する |
| 16 | ファイルの読み書きに失敗した場合（ファイルが存在しない、アクセス権がない等）、アプリを終了せずにエラーメッセージを表示する |

## 4. 要求確認事項（決定事項一覧）

上司の指示は「`FileParserLib`を使い、WPFで読み込み・保存・編集ができるアプリケーションを作成する」のみであるため、以下は本書で提案する内容である。**「要確認」の項目は、レビューで方針を確認する。**

| No | 項目 | 決定内容（案） | 状態 |
|----|------|------|------|
| 1 | 画面構成 | 1つのメインウィンドウで操作する（4-1） | 要確認 |
| 2 | 値の入力方法 | LFCの値の表記（例：`1,"tasiro",2`）で入力する（4-2） | 要確認 |
| 3 | エラーを含むファイルの扱い | エラーがあっても開けるようにし、保存前に警告する（4-3） | 要確認 |
| 4 | コメントの扱い | 画面には表示せず、編集もしない。ライブラリの仕様どおり保存時に保持する | 要確認 |
| 5 | 名前の変更 | キー名・セクション名の変更機能は設けない（6章） | 要確認 |
| 6 | 元に戻す（Undo） | 設けない（6章） | 要確認 |
| 7 | 同時に開くファイル数 | 1つ（別のファイルを開くと置き換わる） | 決定 |
| 8 | 画面の言語 | 日本語 | 決定 |

### 4-1. 画面構成

メインウィンドウを次の領域で構成する。

| 領域 | 内容 |
|---|---|
| メニュー／ツールバー | 新規作成、開く、上書き保存、名前を付けて保存、終了、セクションの追加・削除、キーの追加・削除 |
| セクション一覧（左） | セクション名の一覧。グローバルセクションは「（グローバル）」などと表示して区別する |
| キー一覧（右） | 選択したセクションのキー・値・型の表。値の編集はここで行う |
| 診断情報一覧（下） | 読み込み時の警告・エラーの重大度・行番号・メッセージ |
| ステータスバー | 開いているファイルのパス、セクション数・キー数など |

### 4-2. 値の入力方法

LFCの値は「型が混在する複数値」であるため、入力方法を次のどちらにするかが最も大きな判断となる。

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| A（推奨） | LFCファイルと同じ表記のテキストで入力する（例：`1,"tasiro",2`）。型はライブラリと同じ規則で判定する | ファイルと同じ見た目で、複数値もまとめて入力できる。型判定の規則がライブラリと一致する | LFCの記法を知らないと入力できない |
| B | 要素ごとに「型」と「値」を選んで入力する | 型を明示でき、記法を知らなくても入力できる | 複数値の入力・並べ替えの画面が複雑になる |

- 案Aの場合、表示も同じ表記（保存時と同じ形式）とし、型は別の列に表示する
- 案Aで入力した表記に警告・エラーとなる記述（クォートなしの文字列、閉じていない引用符など）がある場合の扱い（確定前に確認する／確定させない）は、次工程で決める

### 4-3. エラーを含むファイルの扱い

ライブラリは、エラー（重複キー、セクション記法の誤り等）を含むファイルを、既定では例外として扱う。アプリでは次のとおりとする。

- `ThrowOnError = false`で読み込み、エラーがあっても内容を表示する。エラーは診断情報一覧に表示し、メッセージでも通知する
- エラーの行は読み込まれていない（ライブラリの仕様で無視される）ため、そのまま保存すると元のファイルからその行が失われる。エラーを含むファイルを保存する場合は、その旨を表示して確認する
- 診断情報は読み込み時点のものとし、編集しても更新しない（ライブラリの仕様と同じ）

## 5. 非機能要件

| No | 要件 |
|----|------|
| 1 | 開発言語：C#（.NET 8）、UIフレームワーク：WPF。動作環境はWindows 10／11 |
| 2 | 画面（View）と処理を分離する（MVVMパターン）。画面の処理はViewModelに置き、コードビハインドには画面固有の処理だけを書く |
| 3 | ViewModelのロジックは、画面を表示せずにユニットテストで検証できる構成とする（ファイルダイアログ・メッセージボックスはインターフェイス経由で呼び出す） |
| 4 | LFCの読み書き・型判定はアプリで実装せず、`FileParserLib`に任せる |
| 5 | 外部ライブラリは、`FileParserLib`とテスト用ライブラリ（xUnit）以外は使わない（MVVMの基盤も標準機能で実装する） |
| 6 | ファイルの読み書き中に例外が発生しても、アプリを異常終了させない |
| 7 | コーディング規約・フォルダ構成・修飾子の方針は、`FileParserLib`と同じとする（1ファイル1クラス、フォルダと名前空間の一致など） |

## 6. スコープ外（今回は扱わない事項）

- キー名・セクション名の変更（ライブラリに名前を変更するAPIがなく、削除と追加で代用すると位置やコメントが変わるため）
- キー・セクションの並べ替え（ライブラリに並べ替えのAPIがないため）
- コメントの表示・編集
- 元に戻す／やり直し（Undo／Redo）
- 複数ファイルの同時編集、タブ表示
- 検索・置換
- LFCファイル以外の形式（INI、CSV等）の読み書き
- ライブラリ（`FileParserLib`）の仕様変更。必要が生じた場合は別途相談する

## 7. 次工程（基本設計）で検討する事項

- 画面レイアウトの詳細（各領域の配置、コントロールの種類：`ListBox`／`TreeView`、`DataGrid`等）と画面遷移
- ViewModelの構成（メイン画面、セクション、キー行など）と、`LfcDocument`との対応
- コマンド（`ICommand`）と、実行できる条件（例：ファイルを開いていないときは保存できない）
- 案Aを採用する場合、入力した値の表記を`LfcValue`の一覧に変換する方法（ライブラリの公開APIだけで実現できるか。できない場合はライブラリへのAPI追加の要否）
- 保存していない変更の判定方法（編集したら「変更あり」とする／保存した内容と比較する）
- エラーメッセージの文言と表示方法（メッセージボックス、診断情報一覧への追記など）
- ファイルダイアログ・メッセージボックスを抽象化するインターフェイスの設計
- `FileParserLib`の参照方法（DLLを配置する／Gitのサブモジュールにする等）
