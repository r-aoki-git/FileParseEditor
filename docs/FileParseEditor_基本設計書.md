# FileParseEditor 基本設計書

## 1. システム概要

`FileParseEditor`は、LFC（`.lfc`）ファイルの読み込み・編集・保存を画面から行う、Windows用のWPFアプリケーションである。LFCの読み書き・型判定は`FileParserLib`に任せ、アプリは画面の表示と操作の制御だけを行う。

```
[利用者]
   │  操作（メニュー、入力、ドラッグ＆ドロップ）
   ▼
FileParseEditor.exe（WPF）
   │  公開APIの呼び出し
   ▼
FileParserLib.dll
   │  読み込み／書き込み
   ▼
*.lfc ファイル
```

本書は`FileParseEditor_要件定義書.md`の要件を、画面・操作・ソフトウェア構成の設計に落とし込んだものである。要件定義書の「次工程で検討する事項」（7章）は、本書の各章で決定する（12章に対応表を示す）。

## 3. 画面設計

### 3-1. 画面一覧

| 画面 | 種類 | 役割 |
|---|---|---|
| メイン画面 | ウィンドウ | 全ての操作を行う画面。起動時に表示し、終了まで閉じない |
| セクションの追加ダイアログ | モーダルダイアログ | 追加するセクション名を入力する |
| キーの追加ダイアログ | モーダルダイアログ | 追加するキー名と値を入力する |
| ファイルを開くダイアログ | 標準ダイアログ（`Microsoft.Win32.OpenFileDialog`） | 開くファイルを選択する |
| ファイルを保存するダイアログ | 標準ダイアログ（`Microsoft.Win32.SaveFileDialog`） | 保存先のファイルを指定する |
| メッセージ | 標準ダイアログ（`MessageBox`） | 確認・エラーのメッセージを表示する（10章） |

### 3-2. メイン画面のレイアウト

メイン画面は、上から「メニュー」「ツールバー」「作業領域」「診断情報一覧」「ステータスバー」の順に並べる。作業領域は、左から「セクション一覧」「キー一覧と値の編集欄」「保存イメージ」の3列とする。

| 領域 | コントロール | 内容 |
|---|---|---|
| タイトルバー | ― | 「FileParseEditor - ファイル名」。新規作成した文書は「無題」。保存していない変更があれば末尾に「 *」を付ける（F8） |
| メニュー | `Menu` | 3-3 の項目 |
| ツールバー | `ToolBar` | メニューのうち、よく使う操作のボタン |
| セクション一覧（左） | `ListBox` | 3-4-1 |
| キー一覧（中央上） | `DataGrid`（読み取り専用） | 3-4-2 |
| 値の編集欄（中央下） | `TextBox`、`Button` | 3-4-3 |
| 保存イメージ（右） | `TextBox`（読み取り専用、等幅フォント、縦横スクロール） | 3-4-4 |
| 診断情報一覧（下） | `DataGrid`（読み取り専用） | 3-4-5 |
| ステータスバー | `StatusBar` | 3-4-6 |

- 左・中央・右の3つの領域の間と、上下の領域の間には`GridSplitter`を置き、幅・高さを変えられるようにする
- 保存イメージは常に表示する（表示・非表示の切り替えは設けない）。不要な場合は`GridSplitter`で幅を狭める

### 3-3. メニュー

| メニュー | 項目 | ショートカット | 実行できる条件 | 機能ID |
|---|---|---|---|---|
| ファイル | 新規作成 | Ctrl+N | 常に | F2 |
| | 開く… | Ctrl+O | 常に | F1 |
| | 上書き保存 | Ctrl+S | 常に（新規作成した文書は「名前を付けて保存」と同じ動作） | F7 |
| | 名前を付けて保存… | Ctrl+Shift+S | 常に | F7 |
| | 終了 | Alt+F4 | 常に | F8 |
| 編集 | 元に戻す | Ctrl+Z | 元に戻せる履歴がある | F9 |
| | セクションの追加… | ― | 常に | F6 |
| | セクションの削除 | ― | 選択したセクションが文書に存在する | F6 |
| | キーの追加… | ― | セクションを選択している | F5 |
| | キーの削除 | Delete（キー一覧にフォーカスがあるとき） | キーを選択している | F5 |

- 実行できない項目は無効（グレー表示）にする。ツールバーのボタンも同じ条件で無効にする
- Ctrl+Z は、値の編集欄にフォーカスがある間は、`TextBox`の入力の取り消しとして働く（WPFの標準動作）。文書の「元に戻す」は、メニューまたはツールバーから行う

### 3-4. 各領域の表示内容

#### 3-4-1. セクション一覧

- 文書のセクションを登場順に表示する。通常のセクションは、ファイル上の記法と同じく`[Profile]`のように角かっこを付けて表示する
- グローバルセクション（名前が`""`）は「（グローバル）」と表示し、**文書に存在しない場合も常に先頭に表示する**。これにより、グローバルセクションがないファイルでも、選択してキーを追加すれば作成できる（要件定義書7章の検討事項）。ライブラリの`Set`は、グローバルセクションを先頭に作成する
- 起動時・ファイルを開いた後・新規作成の後は、先頭（グローバルセクション）を選択する
- 選択していたセクションが削除・元に戻す操作でなくなった場合は、先頭を選択する

#### 3-4-2. キー一覧

選択したセクションのキーを登場順に表示する。

| 列 | 内容 | 例 |
|---|---|---|
| キー | キー名 | `ID` |
| 値 | 保存時と同じLFCの表記（5章） | `1,"tasiro",2` |
| 型 | 要素ごとの型を「, 」区切りで表示する（`LfcValueType`の名前） | `Int, String, Int` |

- グローバルセクションが文書に存在しない場合は、0件として表示する
- 一覧上では編集しない（読み取り専用）。値の変更は値の編集欄で行う

#### 3-4-3. 値の編集欄

- キー一覧で選択したキーの名前と、値の表記を表示する。キーを選択していないときは入力できない
- 値を書き換えて「確定」ボタンを押すか、Enterキーを押すと、値の変更（6-3）を行う
- 確定する前に別のキーを選択した場合、入力中の内容は破棄し、新しく選択したキーの値を表示する（文書は変更されていないため、データは失われない）

#### 3-4-4. 保存イメージ

- 文書の`ToText()`の結果を表示する。コメントもこの欄で確認する（要件定義書4-5）
- 編集・元に戻す・ファイルを開く・新規作成のたびに更新する
- キーを選択しても、保存イメージの該当行へは移動しない（要件定義書7章の検討事項。行の対応付けには、ライブラリにない情報が必要になるため）

#### 3-4-5. 診断情報一覧

| 列 | 内容 |
|---|---|
| 重大度 | 「警告」（`Warning`）／「エラー」（`Error`） |
| 行 | 行番号（`LfcDiagnostic.Line`） |
| メッセージ | `LfcDiagnostic.Message` |

- ファイルを開いた時点の診断情報を表示し、編集・保存・元に戻す操作では変えない（要件定義書4-3）
- 新規作成した文書では0件とする

#### 3-4-6. ステータスバー

「ファイルのパス（新規作成した文書は「無題」）」「セクション n件」「警告 n件」「エラー n件」を、この順に並べて表示する。セクションの件数は文書に存在するセクションの数とする。

### 3-5. ダイアログ

#### 3-5-1. セクションの追加ダイアログ

| 項目 | コントロール | 内容 |
|---|---|---|
| セクション名 | `TextBox` | 追加するセクション名（角かっこは入力しない） |
| OK／キャンセル | `Button` | OK でダイアログを閉じて追加する（6-6）。キャンセルで何もしない |

#### 3-5-2. キーの追加ダイアログ

| 項目 | コントロール | 内容 |
|---|---|---|
| セクション | `TextBlock` | 追加先のセクション（表示のみ） |
| キー名 | `TextBox` | 追加するキー名 |
| 値 | `TextBox` | 値の表記（空欄の場合は値なし） |
| OK／キャンセル | `Button` | OK でダイアログを閉じて追加する（6-4）。キャンセルで何もしない |

- 入力に問題があった場合（6-4）は、メッセージを表示した後、入力した内容を残したまま同じダイアログをもう一度表示する

### 3-6. 画面遷移

| 遷移元 | 操作 | 遷移先 |
|---|---|---|
| メイン画面 | 開く | （保存していない変更の確認）→ ファイルを開くダイアログ → メイン画面 |
| メイン画面 | 新規作成 | （保存していない変更の確認）→ メイン画面 |
| メイン画面 | 上書き保存（新規作成した文書）、名前を付けて保存 | ファイルを保存するダイアログ → メイン画面 |
| メイン画面 | セクションの追加 | セクションの追加ダイアログ → メイン画面 |

| メイン画面 | セクションの削除 | 確認メッセージ → メイン画面 |

## 4. 起動と終了

- 起動すると、新規作成と同じ状態（空の文書、「無題」）でメイン画面を表示する
- コマンドライン引数でのファイル指定（関連付けによる起動）は扱わない
- メニューの「終了」、ウィンドウの閉じるボタン、Alt+F4 のいずれでも、保存していない変更があれば保存するかを確認する（6-10）。「キャンセル」を選んだ場合は終了しない

## 5. 値の表記の変換

キー一覧・値の編集欄では、値（`IReadOnlyList<LfcValue>`）を、保存時と同じLFCの表記の文字列として扱う（要件定義書4-2）。ライブラリの型判定・書き出しのクラスは非公開のため、**公開APIの`LfcDocument`を使って変換する**（要件定義書7章の検討事項。ライブラリへのAPI追加は不要）。

### 5-1. 値 → 表記（表示）

1. `LfcDocument.CreateEmpty()`で作業用の文書を作る
2. グローバルセクションに、作業用のキー名で値を`Set`する
3. `ToText()`の結果（`K = 1,"tasiro",2`）から、キー名と` = `を取り除いた部分を表記とする。値なしの場合は空文字列とする

### 5-2. 表記 → 値（入力の解釈）

入力を次の順に検査し、最初に当てはまった結果とする。

| 順 | 条件 | 結果 |
|---|---|---|
| 1 | 改行（CR・LF）を含む | 入力エラー（M07）。値の入力欄では改行を扱わない |
| 2 | `LfcDocument.Parse("K = " + 入力)`（`ThrowOnError = false`）の診断情報に Error がある | 入力エラー（M06）。メッセージにはライブラリの診断情報のメッセージを含める |
| 3 | 解釈した文書の`ToText()`が、解釈した値だけを5-1で書き出した結果と一致しない | 入力エラー（M08）。クォートの外の`#`がコメントとして扱われたことを表す |
| 4 | 診断情報に Warning がある | 警告付きで成功。解釈した値と、Warningのメッセージを返す（呼び出し側で確認する。6-3） |
| 5 | 上記のいずれでもない | 成功。解釈した値を返す |

- 空の入力（空白だけの入力を含む）は、ライブラリの規則どおり「値なし」（`LfcValue.Null`1つ）になる
- 型判定・エスケープ・空の要素の扱いは、ライブラリの読み込みと同じになる（同じ処理を通すため）
- 確定した値は文書に`LfcValue`として設定されるため、Warningの記述は保存時にライブラリの規則で正規化される（例：`Auto`→`"Auto"`、`1e3`→`1000.0`）。確認メッセージには、この正規化後の表記を「解釈した結果」として示す

## 6. 操作仕様

各操作は、操作の前に必要な確認を行い、文書を変更する操作では、変更の直前に元に戻すための履歴（6-9）を記録する。ライブラリが例外を送出した場合は、文書を変更せずにメッセージを表示する（9章）。

### 6-1. ファイルを開く（F1）

1. 保存していない変更があれば、保存するかを確認する（6-10）。キャンセルされたら中止する
2. ファイルを開くダイアログで、ファイルを選択する（フィルター：「LFCファイル (*.lfc)」「すべてのファイル (*.*)」）。キャンセルされたら中止する。ドラッグ＆ドロップの場合はドロップされたファイルを使う
3. `LfcDocument.Load(path, new LfcLoadOptions { ThrowOnError = false })`で読み込む。例外が発生した場合は M11 を表示し、現在の文書はそのまま残す
4. 読み込んだ文書・ファイルのパス・診断情報を保持し、元に戻す履歴を消去する。表示を全て更新する
5. 診断情報に Error がある場合は M02 を表示する（Warning だけの場合はメッセージを出さず、診断情報一覧にだけ表示する）

ドラッグ＆ドロップは次のとおりとする。

- メイン画面のどこにドロップしても受け付ける
- ドロップされたのがファイル1つの場合だけ開く。複数のファイル、またはフォルダの場合は M13 を表示する
- 拡張子は問わない（ファイルを開くダイアログで「すべてのファイル」を選んだ場合と同じ）

### 6-2. 新規作成（F2）

1. 保存していない変更があれば、保存するかを確認する（6-10）。キャンセルされたら中止する
2. `LfcDocument.CreateEmpty()`で空の文書を作る。ファイルのパスはなし（「無題」）、診断情報は0件とし、元に戻す履歴を消去する

### 6-3. 値の変更（F4）

1. 値の編集欄の入力を、5-2 の規則で解釈する
2. 入力エラーの場合は、メッセージ（M06〜M08）を表示して終了する。入力した内容は値の編集欄に残す
3. 警告付きの場合は M05 で確認する。「いいえ」の場合は終了する（入力は残す）
4. 解釈した値が現在の値と同じ（`LfcValue`の一覧が等しい）場合は、何もしない（変更として扱わない）
5. 元に戻す履歴を記録し、`Set(セクション, キー, 値)`で設定する。キーの位置とコメントは維持される（ライブラリの仕様）
6. 表示を更新する。値の編集欄には、確定した値の表記（正規化後）を表示する

### 6-4. キーの追加（F5）

1. キーの追加ダイアログで、キー名と値を入力する。キャンセルされたら中止する
2. 選択したセクションに同じ名前のキーが既にある場合は、M09 を表示してダイアログに戻る（ライブラリの`Set`は既存のキーを上書きするため、追加の前に確認する。要件定義書 機能要件No.6）
3. 値を 5-2 の規則で解釈する。入力エラーの場合はメッセージを表示してダイアログに戻る。警告付きの場合は M05 で確認し、「いいえ」の場合はダイアログに戻る
4. 元に戻す履歴を記録し、`Set`で追加する。キー名がLFCとして書き出せない場合はライブラリが`ArgumentException`を送出するため、記録した履歴を取り消し、M10 を表示してダイアログに戻る
5. 表示を更新し、追加したキーを選択する（キーはセクションの末尾に追加される）

### 6-5. キーの削除（F5）

1. 確認は行わない（元に戻すで戻せるため）
2. 元に戻す履歴を記録し、`Remove`で削除する。付いていたコメントも削除される（ライブラリの仕様）
3. 表示を更新する。削除したキーの次のキー（末尾の場合は前のキー）を選択する

### 6-6. セクションの追加（F6）

1. セクションの追加ダイアログで、セクション名を入力する。キャンセルされたら中止する
2. 空のセクション名は M10 を表示してダイアログに戻る（グローバルセクションは常に一覧にあるため、追加の対象としない）
3. 同じ名前のセクションが既にある場合は、M09 を表示し、そのセクションを選択して終了する（ライブラリの`AddSection`は既存の場合に何もしないため、利用者に分かるように表示する。要件定義書 機能要件No.8）
4. 元に戻す履歴を記録し、`AddSection`で追加する。名前がLFCとして書き出せない場合は、記録した履歴を取り消し、M10 を表示してダイアログに戻る
5. 表示を更新し、追加したセクション（末尾）を選択する

### 6-7. セクションの削除（F6）

1. M04 で、セクション名と含まれるキーの件数を示して確認する。「いいえ」の場合は中止する
2. 元に戻す履歴を記録し、`RemoveSection`で削除する
3. 表示を更新する。グローバルセクションを削除した場合も、一覧には「（グローバル）」が残る（3-4-1）

### 6-8. 保存（F7）

**上書き保存**

1. 新規作成した文書（ファイルのパスがない）の場合は、名前を付けて保存と同じ動作をする
2. エラーを含むファイルを開いた後、そのファイルにまだ保存していない場合は、M03 で確認する（要件定義書4-3）。「いいえ」の場合は中止する
3. `Save(path)`で保存する。例外が発生した場合は M12 を表示する（文書と「変更あり」の状態は変えない）
4. 保存した内容を「保存済みの内容」として記録する（6-11）。エラーを含むファイルの確認は、以降は行わない

**名前を付けて保存**

1. ファイルを保存するダイアログで保存先を指定する（初期値は現在のファイル名、新規作成した文書は「無題.lfc」。既存のファイルを選んだ場合の上書き確認はダイアログの標準機能で行う）。キャンセルされたら中止する
2. 保存先が、エラーを含む状態で開いた元のファイルと同じ場合は、上書き保存の 2 と同じ確認を行う
3. 以降は上書き保存の 3・4 と同じ。成功した場合は、保存先を現在のファイルのパスとする

- 文字コード（UTF-8 BOMなし）・改行コード（LF）は、ライブラリの仕様どおりとする
- 元に戻す履歴は、保存しても消去しない（要件定義書4-4）

### 6-9. 元に戻す（F9）

要件定義書7章の検討事項（元に戻すの実現方法）は、次のとおりとする。

- 文書を変更する操作（6-3〜6-7）の直前に、その時点の文書の`ToText()`の結果を履歴に積む
- 元に戻すときは、履歴から最後に積んだテキストを取り出し、`LfcDocument.Parse(テキスト, ThrowOnError = false)`で文書を作り直して、現在の文書と置き換える
- `ToText()`→`Parse`は、ライブラリのラウンドトリップ要件により、セクション・キー・値と、その順序・コメントの位置が一致する。そのため、削除したキーも元の位置とコメントを含めて戻る（`Set`で戻すと末尾に追加され、コメントも失われるため、この方法を採る）
- 履歴は最大100件とし、超えた場合は古いものから捨てる
- ファイルを開く・新規作成で履歴を消去する。保存では消去しない
- 診断情報は作り直した文書のものではなく、ファイルを開いた時点のものを表示し続ける（作り直した文書には、Errorの行がすでに含まれていないため、診断情報は0件になる）
- 元に戻した後は、元に戻す前に選択していたセクション・キーが存在すれば、それを選択する

### 6-10. 保存していない変更の確認（F8）

ファイルを開く・新規作成・終了の前に、保存していない変更がある場合は M01 で確認する。

| 選択 | 動作 |
|---|---|
| はい | 上書き保存（6-8）を行う。保存がキャンセル・失敗した場合は、元の操作も中止する |
| いいえ | 保存せずに元の操作を続ける |
| キャンセル | 元の操作を中止する |

### 6-11. 「変更あり」の判定（F8）

要件定義書7章の検討事項（保存していない変更の判定方法）は、次のとおりとする。

- ファイルを開いたとき・新規作成したとき・保存したときに、文書の`ToText()`の結果を「保存済みの内容」として記録する
- 現在の文書の`ToText()`が「保存済みの内容」と異なる場合を「変更あり」とする
- そのため、編集した後に元に戻して保存時と同じ内容になった場合は、「変更あり」が解除される（要件定義書7章の検討事項）
- `ToText()`は保存イメージの表示（3-4-4）でも使うため、操作のたびに1回だけ呼び出し、両方で使う

## 8. 処理の流れ

利用者・View・`MainViewModel`・`DocumentSession`・`FileParserLib`の間のやり取りを示す。

### 8-1. ファイルを開く（F1）

1. 利用者がメニューの「開く」を選ぶ。`MainWindow`は`OpenCommand`を実行する
2. `MainViewModel`は`DocumentSession.IsModified`を確認し、変更があれば`IMessageService.AskSaveChanges`で確認する（6-10）
3. `MainViewModel`は`IFileDialogService.ShowOpenDialog`でファイルのパスを得る
4. `MainViewModel`は`DocumentSession.Open(path)`を呼び出す。`DocumentSession`は`LfcDocument.Load(path, ThrowOnError = false)`で読み込み、文書・パス・診断情報・保存済みの内容を置き換え、履歴を消去する
5. `MainViewModel`は表示（セクション一覧・キー一覧・保存イメージ・診断情報・タイトル・ステータスバー）を更新する
6. 診断情報に Error があれば、`IMessageService.ShowInformation`で M02 を表示する

読み込みで例外が発生した場合は、4 で例外が`MainViewModel`に伝わり、`IMessageService.ShowError`で M11 を表示する。`DocumentSession`の状態は変わらない。

### 8-2. 値の変更（F4）

1. 利用者が値の編集欄に入力し、「確定」を押す。`MainWindow`は`ApplyValueCommand`を実行する
2. `MainViewModel`は`LfcValueNotation.Parse(EditingValueText)`で入力を解釈する。`LfcValueNotation`は作業用の文書を`LfcDocument.Parse`で作り、5-2 の規則で結果を返す
3. 入力エラーの場合、`MainViewModel`は`IMessageService.ShowError`でメッセージを表示して終了する
4. 警告付きの場合、`MainViewModel`は`IMessageService.Confirm`で M05 を表示し、「いいえ」なら終了する
5. `MainViewModel`は`DocumentSession.SetValue`を呼び出す。`DocumentSession`は`ToText()`の結果を`EditHistory`に積み、`LfcDocument.Set`で値を設定する
6. `MainViewModel`はキー一覧・保存イメージ・タイトルを更新する

### 8-3. 元に戻す（F9）

1. 利用者がメニューの「元に戻す」を選ぶ。`MainWindow`は`UndoCommand`を実行する
2. `MainViewModel`は`DocumentSession.Undo`を呼び出す
3. `DocumentSession`は`EditHistory`から最後のテキストを取り出し、`LfcDocument.Parse(テキスト, ThrowOnError = false)`で文書を作り直して置き換える
4. `MainViewModel`は、選択していたセクション・キーを覚えておき、表示を全て更新した後で、存在すれば選択し直す

### 8-4. 上書き保存（F7）— エラーを含むファイル

1. 利用者がメニューの「上書き保存」を選ぶ。`MainWindow`は`SaveCommand`を実行する
2. `MainViewModel`は`DocumentSession.FilePath`があることを確認する（なければ名前を付けて保存へ）
3. `MainViewModel`は`DocumentSession.NeedsErrorLossConfirmation(FilePath)`が`true`のため、`IMessageService.Confirm`で M03 を表示する。「いいえ」なら終了する
4. `MainViewModel`は`DocumentSession.Save(FilePath)`を呼び出す。`DocumentSession`は`LfcDocument.Save`で書き込み、保存済みの内容を記録する
5. `MainViewModel`はタイトル（「 *」を外す）を更新する

### 8-5. 終了（F8）

1. 利用者がウィンドウの閉じるボタンを押す。`MainWindow`の`Closing`イベントで、`MainViewModel.ConfirmClose`を呼び出す
2. `MainViewModel`は、変更があれば M01 で確認する（6-10）
3. `ConfirmClose`が`false`を返した場合、`MainWindow`は`Closing`をキャンセルし、終了しない

## 9. エラー処理方針

| 発生場所 | 例外・状況 | 対応 |
|---|---|---|
| ファイルを開く | `LfcDocument.Load`の例外（`FileNotFoundException`、`DirectoryNotFoundException`、`UnauthorizedAccessException`、`IOException`、`ArgumentException`等） | M11 を表示する。現在の文書はそのまま残す |
| ファイルを開く | Error を含むファイル | `ThrowOnError = false`で読み込むため例外にならない。M02 で通知する（`LfcFormatException`は発生しない） |
| 保存 | `LfcDocument.Save`の例外（同上） | M12 を表示する。文書と「変更あり」の状態は変えない |
| 編集 | `Set`・`AddSection`の`ArgumentException`（LFCとして書き出せない名前） | M10 を表示する。ライブラリは例外を送出した場合に文書を変更しないため、記録した履歴だけを取り消す |
| 値の入力 | 5-2 の入力エラー | M06〜M08 を表示する。文書は変更しない |
| 全体 | 上記以外の想定外の例外 | `App`の`DispatcherUnhandledException`で受け止め、M14 を表示してアプリを続行する（非機能要件No.6） |

- ライブラリの例外のメッセージ（`Exception.Message`）は、メッセージの「詳細」として表示する
- `DocumentSession`は例外を受け止めずに呼び出し元（`MainViewModel`）へ伝え、メッセージの表示は`MainViewModel`が行う（画面に依存しない処理にメッセージの表示を持ち込まないため）

## 11. 非機能要件の実現方針

| 要件定義書の非機能要件 | 対応方針 |
|---|---|
| No.1 C#（.NET 8）・WPF、Windows 10／11 | アプリは`net8.0-windows`、それ以外は`net8.0`で作成する（7-1） |
| No.2 画面と処理の分離（MVVM） | ViewModel をWPFに依存しない`FileParseEditor.Core`に置く（7-1）。コードビハインドには、ドラッグ＆ドロップ・閉じる前の確認の呼び出し・ダイアログの入力の受け渡しだけを書く |
| No.3 ViewModel の単体テスト | ダイアログ・メッセージをインターフェイス（`IFileDialogService`等）経由で呼び出し、テストでは偽の実装に差し替える。`FileParseEditor.Tests`は画面を表示せずに実行できる |
| No.4 LFCの処理はライブラリに任せる | 値の表記の変換も、ライブラリの`Parse`・`ToText`を使って行い、型判定・エスケープをアプリで実装しない（5章） |
| No.5 外部ライブラリは使わない | MVVMの基盤を自作する（`ObservableObject`・`RelayCommand`）。テストには xUnit だけを使う |
| No.6 例外で異常終了させない | ライブラリの例外は操作ごとに受け止め、それ以外は`DispatcherUnhandledException`で受け止める（9章） |
| No.7 規約は`FileParserLib`と同じ | 1ファイル1型、フォルダと名前空間の一致、修飾子・コレクションの方針、`.editorconfig`（UTF-8 BOMなし、LF）を`FileParserLib`と同じにする |

## 12. 要件定義書7章の検討事項への対応

| 検討事項 | 決定内容 | 本書 |
|---|---|---|
| 画面レイアウトの詳細と画面遷移 | 左：セクション一覧、中央：キー一覧と値の編集欄、右：保存イメージ、下：診断情報 | 3章 |
| 保存イメージの配置と、該当行への移動 | 常に右側に表示する。該当行への移動はしない | 3-2、3-4-4 |
| ViewModel の構成と`LfcDocument`との対応 | `MainViewModel`と一覧の行（record）。文書の操作は`DocumentSession`に任せる | 7-3〜7-5 |
| グローバルセクションにキーを追加する方法 | セクション一覧に「（グローバル）」を常に表示し、選択してキーを追加する | 3-4-1 |
| コマンドと実行できる条件 | 3-3 の表のとおり | 3-3 |
| 値の表記を`LfcValue`に変換する方法 | 公開APIの`Parse`・`ToText`を使う。ライブラリへのAPI追加は不要 | 5章 |
| 元に戻すの実現方法、履歴の上限、「変更あり」の解除 | `ToText()`の結果を履歴に積み、`Parse`で戻す。上限100件。保存時と同じ内容に戻れば「変更あり」を解除する | 6-9、6-11 |

| エラーメッセージの文言と表示方法 | メッセージボックスで表示する。文言は10章 | 9章、10章 |
| ダイアログ・メッセージを抽象化するインターフェイス | `IFileDialogService`、`IMessageService`、`IInputDialogService` | 7-3、7-5 |
| `FileParserLib`の参照方法 | ビルドしたDLLを`lib/`に配置して参照する | 7-2 |

## 13. テスト方針

| 種類 | 対象 | 方法 |
|---|---|---|
| 単体テスト | `LfcValueNotation`、`EditHistory`、`DocumentSession`、`MainViewModel` | `FileParseEditor.Tests`（xUnit）。`MainViewModel`は偽のサービスを渡し、確認メッセージの選択（はい／いいえ／キャンセル）ごとの動作を確認する |
| 画面操作のテスト | 画面の表示・操作の全体 | テスト仕様書に手順と確認項目を記載し、Windows上で手動で操作して確認する |

- 単体テストは、`FileParserLib`と同じく、正常な操作だけでなく、キャンセル・入力エラー・例外の場合に「文書が変わらないこと」「メッセージが表示されること」を確認する
- 画面操作のテストでは、要件定義書の機能要件No.1〜18を全て確認する
